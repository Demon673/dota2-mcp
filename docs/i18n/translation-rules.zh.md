# 翻译规则

[English](translation-rules.md) | 中文

如何在本仓库的一对文档两边之间翻译。英文是权威（[README.md](README.md)）：改动用英文撰写，中文 counterpart 镜像它。这些规则约束生产或更新 counterpart，对人类和 agent 同等有效。规则级别遵循 RFC 2119 用法：**MUST** / **MUST NOT** 是门禁或评审阻塞级；**SHOULD** 偏离需要说明理由；**MAY** 是酌情。

## 忠实

- counterpart *MUST* 说出英文侧说的内容 —— 不加行为、前提、警告、版本声明或示例，也不漏掉任何一条。如果两边在实质上不一致，修正错的那一侧，然后在同一改动里带上另一侧。
- counterpart *SHOULD* 读起来像目标语言的自然技术写作，而不是逐词释义。翻译意思，在目标语法需要处重构句子，并保持作者的语体 —— 简练保持简练。
- 不要翻译不可译的：如果一个句子因为依赖源语言的习语而难以自然表达，翻译意思，而不是习语。

## 语体

- 像母语技术作者复述内容那样写，而不是像译者逐句转写，同时保留每条源句：不加、不漏 —— 流畅永远不是丢句子的理由。
- 当目标语言否则会模糊动作主体时，给句子一个明确的主体；对中文，用实际主体替换含糊的被动或抽象主语。
- 优先目标语言既有的工程惯用语而非硬译；本地化隐喻而不是移植，并在目标语言需要处拆解名词链。
- 按语义单元拆分长段落 —— 一段一个意思。段落边界 MAY 与源不同；结构签名不数段落。
- 译入中文时，类别名词用中文并带首次出现的英文括注；译入英文时，用惯用的英文类别名。字面的目录或文件引用保持代码格式的英文。

## 结构保持

配对门禁检查标题层级、围栏代码块、表格行列数、列表种类、有序列表起始值、列表项数与链接目标。其余框架手工保持；配对文件 MUST 一一匹配于：

- 标题层级（相同级别、相同顺序 —— 标题文本翻译），
- 列表形状与编号，
- 表格（相同列、相同行序；表头单元格按术语翻译），
- 围栏代码块 —— **逐字节相同，含注释**；配对签名比较它们的 info 串与内容，
- 行内代码段（命令、标志、配置键、文件路径、事件名、API 名、版本号）—— 逐字，绝不翻译或重排，
- 链接与锚点：每个相对链接 MUST 在两个文件中指向同一目标 —— 约定是 `.md` 路径，不是 `.zh.md` 兄弟。唯一 zh 专属的链接是语言切换行。链接文本翻译；目标不翻译。

仓库的 Markdown 约定原样适用于 `.zh.md` 文件：一段一行、相对链接可解析。

## 术语

- [terminology.md](terminology.md) 是双向的来源真相。翻译前加载它；每个列出的术语 MUST 遵循它的行与它的「不要译作」禁令。中文目标用「中文」列与其「首次出现」括注；英文目标用「English」列，不加中文括注。
- 对中文目标，未列出的技术术语 MAY 采用主流中文 OSS 或厂商来源的既有译法，并在 PR 中引用。没有这样先例的 MUST 保持英文，并列入「待定术语」附建议译法。
- 对英文目标，用既有的英文技术术语。若源术语没有无歧义的既有对应，保留它并附简短解释性括注，列入待定术语。两个方向都不得内联发明译法；定下的术语在同一 PR 或后续进入 [terminology.md](terminology.md)。

## 排版

这些规则约束中文侧；英文侧遵循仓库常规 Markdown 约定。混排规则遵循 MDN zh-CN 指南、Kubernetes zh-cn 本地化指南、Vue.js docs-zh-cn 约定与中文文案排版指北的跨项目共识：

- MUST 在中文文本与拉丁词之间、中文文本与数字之间放一个半角空格：`每个 plugin 注册 3 个 tool`。全角标点与任何字符之间不放空格。
- MUST 在中文正文中使用全角（中文）标点：`，。：；？！（）「」`。半角标点保留在代码段内、完整英文句引用的原样内，以及数字里（`3.5`、`1,024`）。
- 中文正文 *SHOULD* 优先用冒号、句号、逗号或括号而非破折号。仅当没有其他标点能自然保持句子时保留破折号。
- 枚举逗号：中文并列项列表用顿号（、），不是逗号。
- MUST NOT 使用全角数字或全角拉丁字母 —— `１２３` 绝不，`123` 总是。
- 专有名词保持规范大小写：GitHub、TypeScript —— 除非引用代码，绝不 `github`/`Github`。
- 第二人称是 你，不是 您。
- 强调标记（`**bold**`、`*italic*`）与源保持在同一片段上；中文没有斜体，所以渲染出的强调可能看起来一样 —— 不要用引号或其他装饰替换。

## 质量线

- 当一位双语工程师单独读任一文件都能得到读另一文件读者得到的一切 —— 相同事实、相同注意点、相同语气 —— 且没有多余内容时，一对才算完成。
- 运行 `node scripts/verify-translation-pairing.mjs` 检查记录、切换行、标题层级、代码块、表格行列数、列表种类、有序列表起始值、列表项数与链接。人工评审拥有列表与表格顺序、非规范列表编号、行内代码、强调、含义、术语与语气。
