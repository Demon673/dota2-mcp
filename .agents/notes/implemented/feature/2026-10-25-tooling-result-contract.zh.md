# Agent Note: MCP 工具面统一返回契约

[English](2026-10-25-tooling-result-contract.md) | 中文

Status: implemented

## Problem

驱动 Dota 2 自定义游戏工作的 agent，会把同一次失败读出三种样子，也分不清一份结果是完整还是被截断。控制台输出是尾部窗口、没有游标：同一段读两次还是那些行，漏掉的行不留痕迹。错误是自由文本（中英混排），agent 只能靠模式匹配散文判断该去开 cheats、开 vconsole 还是推进相位。每个工具各返回各的形状——裸文本、原始 JSON、表格——而且一个都没有 MCP annotations，客户端无法提示"这次调用会写文件或重载对局"。另有两个生产缺口完全没有工具：VFX 配方的运动证据（只有单帧截图）与实测帧开销（预算一直写着"未实测"）。

## Decision

所有工具返回同一种契约，且只能由 `src/tools/tool-result.ts` 构造：

- 成功：`{"ok":true, ...payload}`，载荷恰好是三者之一——`lines`（单个换行拼接的字符串，附带 `count`、`next_seq`、`dropped`）、`text`、或带可选 `text` 摘要的 `data`；
- 失败：`{"ok":false, "code": "...", "message": "..."}` 且 `isError: true`；`ERROR_CODES` 只增不减，agent 按 code 分支而不是按文案。

控制台读取是增量的。每行带单调 `seq`，会话持有游标；显式视图（`tail`、`since_seq`、`from_start`，以及 `lines` 作为 `tail` 的一个版本别名）不移动游标，过滤器只在返回窗口内筛选而不消费未匹配行，首次无游标调用取最近 50 行。`console_send` 用每次调用自己的标记闭合窗口，并把游标推进到该窗口之后——"发一条命令、看这条命令的输出"是原子的，同时延迟输出仍然可读。

`dota_status` 用实时事实回答"现在能做什么"（`daemon`、`vconsole`、`dota`、`phase`、`cheats`、`addon`、`map`、`available_actions`），连接类与相位类错误都指向同一组名字。

所有工具都带四类 MCP hint，描述遵循五段式（何时用、做什么、返回什么、上限、相关工具）。任一缺失都会被离线断言的构建拦住。

新增三个工具，同样遵守契约：

- `dota_record` 通过 Windows.Graphics.Capture 捕获**窗口**而不是桌面区域：屏幕裁切会把游戏前面的东西录进去，这是活体验收实测到的。它复用既有截图助手采集、用 ffmpeg 编码；当失焦的游戏停止出帧时，它会向已连接的控制台请求 `r_always_render_all_windows 1`、重试一次并还原原值。
- `dota_perf` 封装固定版本、经 sha256 校验的 PresentMon，输出 p50/p95/p99 并支持基线对比。PresentMon 需要管理员终端；工具会直接说明，而不是返回空采样。
- `dota_test_run` 在引擎内加载 `scripts/vscripts/tests/<name>.lua`，每条测试走独立控制台语句，因此单条失败不中断其余，挂起由单条与整体两级预算兜住。

## Alternatives considered

- **用结构化行对象数组代替单个字符串。** 否决：逐行对象会把 agent 当作文本读的输出放大成数倍 token，而预算信息（`count`、`next_seq`、`dropped`）本来就在字符串旁边以结构化形式给出。
- **双轨形状——旧文本与新信封永久并存。** 否决：契约的意义就是 agent 不必猜形状，永久保留第二种形态会抵消它。旧参数名保留一个版本，工具名不改。
- **照搬 Roblox Studio MCP 的多实例路由（`studio_id`）与客户端执行目标（`datamodel_type`）。** 否决：Dota 是单进程；我们的客户端侧工作是控制台命令而不是 Luau 沙箱，这两个参数在没有第二种情形时只是仪式。
- **为所有长操作引入 `async`/`jobId` 模型。** 推迟：控制台族没有长操作，生命周期工具需要单独一轮设计，而不是偷偷塞进第一个用例。
- **以 mock 为基础的 Lua 单测。** 否决作为主路径：自定义游戏真正出错的地方是引擎 API，所以测试工具在游戏内运行；纯逻辑测试留给项目自己的运行器。
- **用 ddagrab 录制。** 活体验收后否决：它截取的是桌面区域，窗口被遮挡时录到的是前面的浏览器。它本是更小的第一步，是那次实测把它排除掉的。

## Consequences

这是一次破坏性变更，以 2.0.0 发布；迁移表在 `CHANGELOG.md`。原有的、断言原始内容的脚本需要改成读取信封里的字段——行为级断言全部保留，形状级断言被有意更新。

接受的代价：游标随 MCP 会话存在，会话重启即重置，而且会话只能看到自己接入之后产生的输出（daemon 不重放历史）。多行 `console_send` 现在合成一条语句，因此会断开连接的命令（`disconnect`）要等收集超时并返回部分窗口、不推进游标——描述里写明了这一点。`dota_record` 在大窗口上跑高帧率时，因为助手内联编码 PNG 可能跟不上实时。

换来的：重复读取不再重复，漏读以 `dropped` 如实报告，失败可按 code 分支，每个工具都标明风险，以及三项此前做不到的检查——运动证据、帧开销实测、游戏内断言——现在都存在。活体验收在一局运行中的游戏上覆盖了能力矩阵、游标/回显读取、Lua 通道、带 precache 判定的预览、后台窗口录制（抽帧确认是游戏窗口而不是前台应用）、PresentMon 的提权错误，以及一个真实测试文件返回的 pass/fail/继续执行。
