# Agent Note: 从已发布标签重新构建发布产物

[English](2026-11-05-release-tag-rebuilds.md) | 中文

Status: implemented

## 问题

托管 runner 可能在发布构建开始前耗尽容量。恢复对应平台需要重新构建已发布的源码，而手动工作流通常检出包含工作流定义的分支。

## 决策

手动触发必须指定已发布的版本标签。检出源码和上传产物均使用该标签；工作流在安装依赖前检查它与包版本及现有 GitHub Release 一致。发布事件使用事件自身的标签。上传前运行现有构建、离线冒烟集和可执行文件启动检查。

macOS 任务使用受支持的 `macos-15` ARM64 镜像，让恢复构建可以尝试 `macos-latest` 镜像队列之外的选择。

## 考虑过的替代方案

**仅重试 `macos-latest`。** 多次获取 runner 失败后，尝试其他受支持镜像有实际价值。两条队列仍可能同时受到 ARM 容量限制。

**移动已发布的标签。** 消费者已经依赖该源码标识；重新构建直接以现有标签为目标。

**使用 Intel runner。** 这会改变 macOS 可执行文件的原生架构。

## 后果

工作流定义可以独立于待重新构建的源码版本修复。手动触发会重新构建全部三个平台，并将缺失的产物上传到所选 Release；已有产物保留。包内容变更需要发布另一个版本。macOS 镜像固定到其支持情况或构建要求变化时再调整。
