# Agent Note: 游戏截图工具

[English](2026-10-18-dota-screenshot.md) | 中文

Status: proposed

## Problem

测试 addon 的 agent 看不到游戏画面。地图一直加载不出来、相位一直不推进、或者控制台不再应答时，唯一的证据是控制台文本，而活体运行表明这些文本可能对真实状态只字不提：比如一次根本没开始的启动，或者 addon 正停在队伍选择界面上等待。这时只能由开发者看屏幕再描述出来。通过引擎控制台截图在这些情况下恰恰帮不上忙，因为它需要游戏能响应、控制台连接正常。

## Proposal

`dota_screenshot` 工具返回一张游戏截图（见 `GLOSSARY.md`）：从游戏外部获取的 Dota 2 游戏窗口画面。

- **来源**：对游戏视口窗口使用 Windows.Graphics.Capture，即 `dota2.exe` 标题为 "Dota 2" 的顶层窗口。tools 模式下的其他窗口不在范围内。截图从不给游戏发消息、从不使用控制台，所以游戏卡死时仍能拿到它最后合成的一帧。
- **后台**：游戏窗口不需要焦点、也不需要置顶；挡在它前面的窗口不会被截进来；不截鼠标指针；系统允许时关闭截图边框。
- **隔离**：截图在子进程中执行，硬超时 5 秒；超时就杀掉子进程并报错。工具不受 vconsole 门控，relay 断开时也能用。
- **辅助程序**：一个小的 C# 截图辅助程序，在用户机器上用 Windows 自带的 .NET Framework `csc.exe` 编译一次，像 VRF CLI 一样缓存到 `os.tmpdir()/dota2-mcp/` 下。仓库不附带任何二进制文件。
- **游戏卡死**：`IsHungAppWindow` 报告窗口无响应时，照常返回图片，并附上 `hung: true` 和一条说明。
- **窗口最小化**：`restore`（默认 `true`）时，工具以不激活的方式恢复窗口，最多等 2 秒拿到新的一帧，截图后再以不激活的方式重新最小化。`restore: false` 时报告窗口已最小化。如果游戏以独占全屏运行且已最小化，工具报错并建议改用窗口化或无边框模式，而不是恢复窗口。未最小化的窗口立即截图，没有任何等待。
- **输出**：缩放到 `max_width`（默认 1280），按 `format` 编码（默认 `jpeg` 质量 80，或 `png`），作为 MCP image 内容与保存的文件路径一起返回。文件存到 `os.tmpdir()/dota2-mcp/screenshots/`，保留最近 20 张。
- **没有 Dota 窗口**：报错。工具绝不退回截取整个屏幕。
- **平台**：只支持 Windows；其他平台上工具返回错误。
- **其他工具**：`dota_launch_game` 与 `dota_advance_to_game` 的卡相位报告会提到 `dota_screenshot`；没有工具会自动附带截图。

## Alternatives considered

- **引擎控制台 `screenshot` / `jpeg`。** 否决：需要游戏能响应、控制台已连接，而这正是最需要截图时缺失的条件。
- **对窗口 DC 做 GDI `BitBlt`。** 否决：DirectX 窗口通常截出来是黑的，被遮挡的区域也截不到。
- **带 `PW_RENDERFULLCONTENT` 的 `PrintWindow`。** 不作为主路径：它要等游戏的消息循环，游戏卡死时会跟着阻塞。如果 WGC 辅助程序无法从源码构建，它作为退路保留。
- **DXGI 桌面复制。** 否决：它截取整个显示器，包括挡在游戏前面的窗口。
- **附带预编译的截图程序。** 否决，除非事实证明截取卡死的游戏不可或缺、而源码编译的辅助程序又走不通：它打破了"无外部二进制依赖"的约定。
- **恢复最小化窗口后保持恢复状态。** 否决：重新最小化能让桌面回到开发者离开时的样子。

## Acceptance criteria

- 游戏窗口在前台、被遮挡、在后台三种情况下，都只返回游戏画面，且不抢焦点。
- 被 Lua 死循环卡死的游戏，仍能在超时内返回一张标注 `hung: true` 的图片。
- 最小化的窗口会被不激活地恢复、截图、再重新最小化；`restore: false` 时工具报告窗口已最小化。
- 没有 `dota2.exe` 窗口时，工具返回错误，什么也不截。
- 有一个离线测试，在没有 Dota 的情况下覆盖工具的错误路径与输出处理。

## Risks

- 未验证：`csc.exe` 能否引用 WGC 所需的 WinRT 元数据，以及截图边框能否关闭。如果辅助程序无法构建，退路会失去截取卡死游戏的能力。
- 未验证：Windows 用"无响应"占位窗口替换卡死的窗口之后，WGC 返回的是什么。
- 恢复最小化窗口时，窗口会在屏幕上短暂闪一下。独占全屏的检测可能不可靠；书面的退路是建议使用窗口化或无边框模式。
- 图片会消耗 agent 的 token；默认尺寸限制了开销，但没有消除它。
