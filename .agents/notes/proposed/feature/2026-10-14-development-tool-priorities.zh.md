# Agent Note: CustomGame 开发工具优先级

[English](2026-10-14-development-tool-priorities.md) | 中文

Status: proposed

## Problem

[CustomGame 接入调查](../../../../research/2026-10-14-dota2-ai-integration.md)列出了若干可能的扩展，但它们的开发价值与实现确定性各不相同。仅有一份能力清单，无法确定先做什么。优先级应反映日常开发任务、能省下的手工劳动，以及接入确实可行的证据。

## Proposal

优先开发能把引擎输出、资源或运行时观察关联到开发者实际编辑源码的工具。复用客户端文件与终端工具、现有控制台连接，以及 Valve/VRF 工具。本提案记录开发顺序，不构成实施授权。P0 指本队列中的第一项，不是发布阻断项。此处的优先级标签不改变仓库的 FIXME/TODO/XXX 语义。

| 优先级／次序 | 能力 | 开发价值 | 初始范围 |
|---|---|---|---|
| P0 / 1 | TSTL 运行时报错映射 | 不必手工翻查 bundle，就能定位生成 Lua 报错背后的 TypeScript 源码 | 沿用已有的 [dota_map_error 提案](2026-08-05-dota-map-error-tool.md)：产物路径与报错行 → 源文件、行与上下文。显式报告映射缺失、产物过期或未经验证、格式不支持，以及文件名有歧义 |
| P1 / 2 | 资源路径查找与读取，含 VPK 条目 | 找到实际的模型、贴图、声音等资源；区分松散文件缺失与资源缺失 | 先解析 addon 与官方松散文件；用 VRF 做资源包搜索与选定条目的读取／提取。把结果接到现有资产工具上；报告未执行的资源包检查 |
| P1 / 3 | 地图实体读取与查询 | 不必手工翻查一份转出来的大地图，就能找到出生点、触发器、实体名、位置与属性 | 用 dmxconvert 转换一份副本，按 classname/targetname 过滤。只读；不回写地图 |
| P2 / 4 | 运行时 Panorama panel 检查 | 用运行时证据诊断 panel 不显示、被裁掉或样式不对的问题 | 已实现为 `panorama_exec_js`：临时 HUD 桥，提供面板、几何、游戏状态与事件 helper；调试器检视路径仍未完成 |
| P2 / 5 | 粒子预览的 owner 与多个 control point | 不必反复写初始化 Lua，就能预览光束与实体挂点 | 扩展现有 vfx_preview 参数；对照实际效果验证 owner 与 CP 行为 |
| P3 / 6 | 资源构建新鲜度检查 | 判断某个源资源是否需要重新构建 | 验证 resourcecompiler 的 -dependency_check_only 输出与退出行为，再考虑在现有 compile 工具上加一个选项 |

Panorama panel 检查已实现为 `panorama_exec_js`；剩余队列从报错映射与资源查找开始，随后是地图查询。

各项范围仍由已有的[报错映射提案](2026-08-05-dota-map-error-tool.md)、[资产摘要 note](../../implemented/feature/2026-08-20-asset-inspect.md)、[引用检查 note](../../implemented/feature/2026-08-20-asset-check-refs.md)和[粒子预览 note](../../implemented/feature/2026-08-20-vfx-preview.md)定义。这个排序不取代这些记录，也不承诺提案中的扩展已经存在。

## Alternatives considered

**把普通构建与文件编辑再包一层 MCP 工具。** 客户端终端与文件工具已经能处理这些任务。只补缺失的引擎操作或诊断，而不是再加一层 BuildTools。

**优先做业务快照、场景框架、平衡性测试或游戏内 AI 应用。** 这些依赖具体的项目需求，且往往要项目自己维护代码。它们提供不了本队列所瞄准的通用开发价值。

**从地图回写或完整编辑器自动化做起。** 地图转换目前只在一份模板副本上验证过；编辑器自动化接口仍未确认。两者都没有足够证据排在更小的读取与诊断操作之前。

## Acceptance criteria

- 报错映射能将一次真实的 TSTL 运行时报错定位到正确的源码位置，并通过离线检查覆盖映射缺失、不支持、过期与有歧义的情况。映射是否可用取决于实际构建产物；不要假定每份 TSTL 产物都带映射表。
- 资源查找要报告条目在哪里找到、核对过哪些来源。它处理松散与打包资源时，不把未检查的资源包条目标为缺失，并在核对过选项后复用已固定的 VRF 版本。
- 地图查询要从有代表性的源地图返回所请求的实体与属性，同时不动原件。转换失败与版本不支持都显式报出。
- Panorama 只在实测确认目标上下文里的输出可用之后才开始实现。粒子预览的改动需要实测 owner/CP 与视觉验证；新鲜度检查需要实际观察到「已是最新」与「需要重新构建」两类用例。
- 每项实现出来的能力都要证明减少了手工步骤，或取得了原来拿不到的证据。专用工具带不来实际价值时，保留原生工作流。

## Risks

TSTL 映射格式各不相同；过期产物与源文件 basename 都可能让定位产生歧义。静态映射不得依赖运行时 traceback 支持。

资源清点只反映一个安装环境，不能证明覆盖完整。资源包里存在某资源，不证明引擎会挂载或渲染它；提取也不保证得到完整可编辑的工程。

观察到的地图转换把 vmap 格式版本从 20 改到 40，反向编码也不是字节相同。转换成功并不等于回写、编译或加载是安全的。

Panorama 里的字符串不证明命令已经注册或可调用。编辑器 DLL 不证明不存在自动化接口。证据缺失时，这些接入就仍然是有条件的。
