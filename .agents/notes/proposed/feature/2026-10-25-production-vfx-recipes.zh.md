# Agent Note: 生产级 VFX 配方与视觉验收

[English](2026-10-25-production-vfx-recipes.md) | 中文

Status: proposed

## Problem

当前 `dota2-vfx` skill 用一个最小光晕证明了资产管线可用，但并不能教会 agent 制作可用的玩法特效。真正的特效同时涉及视觉意图、父子系统、材质、控制点、挂接、时序、end-cap 行为、性能和 ability 接入。语料统计与合法字段清单无法替代这些决策；一个可见但通用的 sprite，也不能证明 agent 能做出投射物、范围预警或在游戏中实际生效的增益效果。

## Proposal

建立一个小型、可执行的课程，而不是更大的文字参考库。每个配方都有明确的玩法目的和验收路径，并且源格式安全、经过引擎验证。

### 配方契约

每个配方都必须包含：

- **意图与可读性**：玩法提示、形状、颜色职责、半径、持续时间，以及玩家必须识别的信息。
- **完整资产**：全部父子 `.vpcf` 源文件及所需材质/纹理引用。编写源格式安全的 KV3；不把 VRF 展开后的输出当作编写指南。
- **运行时映射**：控制点编号与含义、挂接实体/挂点、位置和方向要求，以及预览或 ability 所需的 `SetParticleControl*` 调用。
- **时序与生命周期**：emitter 类型、生命周期、延迟、淡出/end-cap 行为、循环或爆发，以及如何停止实例而不泄漏。
- **玩法接入**：创建和销毁特效的 ability/modifier 钩子、应由数据驱动的队伍/颜色/持续时间参数，以及服务器权威边界。
- **预算与证据**：相对基线测得的粒子数和帧开销、由测量支持的预算、已知降级方式、分时预期画面，以及改造时的常见陷阱。

每个配方都能通过 `dota2_skill` 独立检索。agent 按意图选择配方，而不是阅读整个 skill 或整份语料。

### 初始课程

先实现并验证三个配方，再考虑扩充：

1. **范围预警 + 命中爆发**：具有精确半径和持续时间的地面预警，随后接短促爆发。覆盖控制点定位、预警可读性、定时子系统和清理。
2. **投射物 + 轨迹 + 命中**：带方向轨迹的移动源和终点效果。覆盖起点/前向映射、飞行时序、挂接替代方式和终点清理。
3. **持续增益/减益光环**：挂接在实体上、队伍职责明确且可显式停止的效果。覆盖挂接、循环生命周期、时长变化和 modifier 销毁时的移除。

只有通过这三项后，才考虑引导光束或更专门的配方。第一切片不做几十个未经验证的模板目录。

### 预览与玩法接入支持

只在配方暴露真实限制时扩展 `vfx_preview`：多控制点、方向、实体挂接和重播/重启。新增任何 ParticleManager API 前，都必须通过活体控制台核对名称和签名。现有简单调用路径保持兼容。分时截图是首选验收机制；是否增加视频或序列帧捕获需要单独决策，因为当前截图工具明确只负责单帧。

还必须在真实 ability/modifier 中验证，而不只是通过预览工具验证。正确的世界坐标预览不能证明英雄挂接或 ability 时序正确。

`vfx_preview` 目前只扩展了一处，这个选择也顺带说明了为什么答案不能去问控制台：未声明的资产照样返回有效 id，照样出现在 `cl_particles_dumpsimlist` 里，引擎输出里没有任何东西能区分“画出来了”和“没画”。工具改为扫 addon 的 `scripts/vscripts` 找有没有 `PrecacheResource` 声明该路径，没有就返回 `precache: MISSING` 和需要补的那一行。多控制点、方向、实体挂接和重播不进工具，配方里可复制的 `dota_run_lua` 片段已经覆盖它们。

## 当前证据

addon 自建粒子现在能端到端显示。AoE 预警用本项目自己生成的贴图画出了半径 500 的圆环，父系统里延迟 1.5 秒的命中子特效也按预期触发，两者都在分时截图中拍到。

此前的所有“看不见”都来自两个编写陷阱，它们属于配方契约，而不是排错附录：

- **控制点绑定。** `m_nControlPointNumber` 和简写的 `m_TransformInput = { m_nControlPoint = 0 }` 都会被 resourcecompiler 静默丢弃。只有完整结构体（`m_bUseOrientation`、`m_nControlPoint`）能保留，也只有这样 `SetParticleControl` 才真正决定特效位置。
- **Precache。** 没有写进 addon `Precache(context)` 的粒子永远不会被绘制，而创建调用照样返回有效 id、系统照样出现在 `cl_particles_dumpsimlist` 里。precache 发生在加载期，所以正确做法是加上条目并重载地图。

还有第三个陷阱会污染验收本身：游戏窗口失焦后停止出帧，`dota_screenshot` 会返回旧图。每张验收截图都必须确认 `stale: false`。

**modifier 集成。** 光环配方现在跑在真实 modifier 里，而不只是预览工具：`LinkLuaModifier` 在加载期注册，`OnCreated` 把系统挂到父单位上，`OnDestroy` 销毁它。`duration = 8` 施加时创建时就画出来、时长到期后画面干净；`duration = 60` 施加后按名字移除同样干净。服务端日志里每次创建都有对应的销毁。预警和投射物两个配方目前仍只经过分时预览验证。

## Alternatives considered

- **增加更多语料统计和文字说明。** 否决：它们能补充参考覆盖，但无法教授组合、时序、接入或验收。
- **发布大量 VRF 反编译的官方特效。** 否决：反编译会填充默认值，也可能暴露不适合手写源文件的旧字段。可以研究官方效果，但交付配方必须源格式安全并经过活体验证。
- **把非零粒子 PID 或一个可见 sprite 当作成功。** 否决：创建不代表可见、位置正确、时序正确、玩法接入正确、性能合格或清理完整。
- **从视频生成开始。** 第一切片否决：完整资产和分时视觉检查是前提；视频只是后续可选的验收辅助，不是知识来源。

## Acceptance criteria

- 三个初始配方都能编译、通过 `asset_check_refs`，并在干净测试 addon 和一个活体 addon 中产生预期可见结果。停止或 modifier 销毁后没有加载错误或实例泄漏。
- 每个配方都交付上述全部契约，包括运行时映射、时序、玩法接入、实测预算和分时预期画面。不依赖未说明的控制点或未命名材质。
- 新 agent 只需按照一个配方修改颜色、半径和持续时间，就能在不使用非法字段或改动结构的情况下完成编译 → 预览 → 视觉验收 → 停止。
- 检索只返回选中的配方及其必要资产，不返回整份语料报告。离线测试覆盖配方检索和结构；活体证据记录在 implemented Agent Note 中。

## Risks

- Particle API 和可接受的 KV3 字段会随引擎版本变化；每个配方都必须针对运行中的引擎验证，并记录验证环境。
- 预览可能掩盖玩法接入错误，因此 ability/modifier 验证是必需项，不是可选项。
- 帧开销测量依赖机器和场景；预算必须写明测量环境，不能变成通用常数。
- 分时静态图片可能遗漏运动伪影。如果无法用图片评估配方的关键行为，就必须单独批准运动捕获路径，而不能降低验收标准。
